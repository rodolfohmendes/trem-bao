1. CSPM: detectar bucket de armazenamento público  Parcial

Postura de segurança em nuvem · prioridade Média · critérios C1
Resumo
Detectar um bucket de armazenamento exposto à Internet e mostrar o alerta com os passos de remediação.
Descrição
Um bucket de armazenamento mal configurado com acesso público de leitura é uma causa comum de exposição de dados. Este teste faz o onboarding de uma conta de nuvem somente leitura, cria um bucket público e verifica a detecção e as orientações de remediação.
Pré-requisitos
  • ✓ Atendido — Read-only cloud account onboarded (Sandbox cloud account onboarded with read-only permissions.)
Objetivos e passos
  • ✗ Não feito — Fazer o onboarding de uma conta de nuvem com permissões somente leitura.
  • Passos do teste:
  • ✓ Feito — Criar um bucket de armazenamento com acesso público de leitura.
  • ✗ Não feito — Aguardar a próxima varredura e abrir o alerta.
  • ✓ Feito — Mostrar os passos de remediação no alerta.
Resultado esperado — ✗ Não atendido
Um alerta é gerado para o bucket público com severidade, recurso afetado e passos de remediação.

2. ZTNA para aplicação privada  Não iniciado

Acesso remoto seguro · prioridade Média
Resumo
Fornecer acesso de menor privilégio a uma aplicação web privada sem expor a rede.
Descrição
Uma aplicação web privada hospedada no data center deve ser acessível apenas por um grupo autorizado. Este teste publica a aplicação por meio do Prisma Access com um ZTNA Connector e concede acesso por grupo de usuários.
Pré-requisitos
  • · Não verificado — Test endpoint with GlobalProtect agent
Objetivos e passos
  • · Não avaliado — Implantar um ZTNA Connector ao lado da aplicação privada.
  • · Não avaliado — Permitir o acesso apenas aos membros do grupo autorizado.
  • · Não avaliado — Verificar que outros hosts da mesma sub-rede não são alcançáveis.
Resultado esperado — · Não avaliado
Os usuários autorizados alcançam a aplicação; usuários não autorizados e outros hosts são bloqueados.
Métricas de avaliação
MétricaMedidoAvaliação
Aprovado/Reprovado——
Como testar
1) Reservar a VM de laboratório de ZTNA conforme descrito em [link interno omitido]. 2) Implantar a VM do ZTNA Connector na rede da aplicação. 3) Adicionar a aplicação como destino no Strata Cloud Manager. 4) Criar uma regra de segurança que permite ao grupo autorizado alcançar a aplicação. 5) Testar o acesso com um usuário autorizado e com um não autorizado.

3. Playbook de contenção automatizada  Não iniciado

Automação de resposta a incidentes · prioridade Média
Resumo
Executar um playbook que isola o endpoint, bloqueia o indicador no firewall e abre um ticket.
Descrição
Hoje a contenção depende de passos manuais entre três equipes. Este teste dispara um playbook a partir de um incidente de malware que isola o host, adiciona o domínio malicioso a uma external dynamic list e abre um ticket no sistema de tickets.
Pré-requisitos
  • · Não verificado — XDR agent installed on test hosts
  • · Não verificado — Log forwarding to Strata Logging Service (Firewall log forwarding profile sending traffic, threat and URL logs.)
Objetivos e passos
  • · Não avaliado — Disparar o playbook automaticamente a partir de um incidente de malware.
  • · Não avaliado — Isolar o endpoint afetado.
  • · Não avaliado — Bloquear o domínio malicioso no firewall por meio de uma external dynamic list.
  • · Não avaliado — Abrir um ticket com o resumo do incidente.
  • · Não avaliado — Medir o tempo desde a detecção até a contenção.
Resultado esperado — · Não avaliado
- O endpoint é isolado. - O domínio é bloqueado no firewall. - Um ticket é aberto sem ação manual.

4. Cortex XDR: isolate a compromised endpoint  Não iniciado

Automação de resposta a incidentes · prioridade Média
Resumo
Isolate a compromised endpoint from the network while keeping it connected to the console for investigation.
Descrição
When an endpoint is compromised, the SOC must cut its network access quickly without losing visibility. This test isolates a lab host from the console and verifies that only the console communication remains.
Pré-requisitos
  • · Não verificado — XDR agent installed on test hosts
Objetivos e passos
  • · Não avaliado — Isolate the host from the console.
  • · Não avaliado — Verify that the host can still be investigated with Live Terminal.
Resultado esperado — · Não avaliado
